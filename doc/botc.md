## 1. 游戏概述

**血染钟楼**（Blood on the Clocktower）是一款社交推理类桌游，官方规则可支持更大规模；当前实现未包含旅行者机制，适用于 **5~15 名实际玩家**（可另设说书人或系统说书人）参与。

### 核心特点

| 特性 | 说明 |
|------|------|
| 游戏人数 | 当前实现：5 ~ 15 名实际玩家（未实现旅行者机制；可另设说书人或系统说书人） |
| 官方剧本 | 三个官方剧本：暗流涌动（Trouble Brewing）、黯月初升（Bad Moon Rising）、教派与紫罗兰（Sects & Violets） |
| 说书人模式 | 支持**玩家说书人**模式和 **AI 说书人**模式 |
| 私聊系统 | 支持玩家间**一对一私聊** |

### 游戏背景

在鸦木布拉夫小镇的钟楼之下，恶魔及其爪牙在夜色中出没。善良的镇民们必须在白天的讨论中找出隐藏在人群中的邪恶力量，并在夜晚降临前将其处决。然而，恶魔每晚都会夺走一条生命……镇民能否在全军覆没之前揪出真凶？一切取决于你的推理、演技和说书人的裁决。

## 2. 角色分类

游戏中的角色分为六大类别，每类角色在游戏中有不同的定位和胜利目标。

### 2.1 镇民（Townsfolk）

- **所属阵营**：善良阵营
- **角色定位**：拥有信息获取、保护、调查等特殊能力
- **胜利条件**：恶魔死亡且场上无法产生新的恶魔
- **特点**：镇民是善良阵营的主力，通过各自的能力收集信息，协助团队找出恶魔

### 2.2 外来者（Outsider）

- **所属阵营**：善良阵营
- **角色定位**：能力通常带有负面效果，可能无意中帮助邪恶阵营
- **胜利条件**：与善良阵营一致
- **特点**：外来者的存在增加了游戏的不确定性，善良阵营需要谨慎处理外来者的信息

### 2.3 爪牙（Minion）

- **所属阵营**：邪恶阵营
- **角色定位**：辅助恶魔，拥有各种干扰和欺骗能力
- **胜利条件**：与邪恶阵营一致
- **特点**：爪牙知道谁是恶魔，负责保护恶魔身份不被暴露，并扰乱善良阵营的判断

### 2.4 恶魔（Demon）

- **所属阵营**：邪恶阵营
- **角色定位**：邪恶阵营的核心，每晚可以杀死一名玩家
- **胜利条件**：场上只剩 2 名存活玩家（含恶魔），或满足特定剧本胜利条件
- **特点**：恶魔是邪恶阵营的唯一杀人手段，恶魔死亡通常意味着善良阵营的胜利

### 2.5 旅行者（Traveler）

- **所属阵营**：可选的额外角色
- **角色定位**：可在游戏过程中随时加入或离开游戏
- **特点**：旅行者的加入增加了游戏的灵活性，适合中途加入的新玩家

### 2.6 传奇角色（Fabled）

- **所属阵营**：说书人辅助角色
- **角色定位**：为说书人提供额外的规则工具或特殊机制
- **特点**：传奇角色是可选的，由说书人决定是否在剧本中使用

## 3. 官方剧本

本游戏支持三个官方剧本，每个剧本都有独特的角色组合和游戏风格。

## 4. 游戏流程

### 流程概览

```
准备阶段 (SETUP)
    |
    v
首个夜晚 (FIRST_NIGHT)  ---  按首夜顺序表依次唤醒角色
    |
    v
第一个白天 (DAY)  ---  讨论 -> 提名 -> 投票 -> 处决
    |
    v
后续夜晚 (NIGHT)  ---  恶魔杀人 + 角色按夜间顺序表行动
    |
    v
后续白天 (DAY)  ---  讨论 -> 提名 -> 投票 -> 处决
    |
    v
  (循环 NIGHT/DAY 直到游戏结束)
```

### 4.1 准备阶段（SETUP）

1. **选择剧本**：房主从三个官方剧本中选择一个（暗流涌动 / 黯月初升 / 教派与紫罗兰）
2. **确定说书人模式**：
   - 玩家说书人模式：房主指定一名玩家担任说书人
   - AI 说书人模式：由 AI 自动主持游戏
   - 无说书人模式：由系统自动处理
3. **玩家准备/确认**：所有玩家确认就位
4. **角色分配**：系统自动根据剧本和人数分配角色

### 4.2 首个夜晚（FIRST_NIGHT）

首个夜晚有特殊的行动顺序，主要用于信息类角色获取初始信息。

**首夜特殊流程**：
1. 部分角色按**首夜顺序表**依次被唤醒执行行动
2. 信息类角色（如 Washerwoman、Librarian、Investigator、Chef、Empath 等）获得初始信息
3. 恶魔及其爪牙被唤醒，互相确认身份
4. 恶魔被唤醒选择首夜击杀目标

> 首夜顺序与后续夜晚的顺序不同，部分角色只在首夜行动。

### 4.3 白天（DAY）

每个白天包含以下阶段：

1. **公开讨论**：所有存活玩家（包括死亡玩家）可以自由发言
2. **提名**：任何玩家可随时提名另一名玩家
3. **投票**：被提名后进入投票阶段，其他玩家投票是否支持处决
4. **处决**：得票最多的玩家被处决（死亡）

> 死亡玩家仍可在白天发言，但只能投票一次（遗言票）。

### 4.4 后续夜晚（NIGHT）

每个夜晚包含以下阶段：

1. **恶魔行动**：恶魔被唤醒选择击杀目标
2. **角色行动**：其他角色按**夜间顺序表**依次被唤醒执行行动
3. **结算**：处理所有行动结果

### 4.5 循环

夜晚和白天交替进行，直到满足胜负判定条件。

## 5. 胜负判定

### 善良阵营胜利条件

- **恶魔死亡**且场上无法产生新的恶魔
- 满足特定角色的特殊胜利条件（如 Mayor 的 3 人存活条件）

### 邪恶阵营胜利条件（满足任一即胜利）

1. **人数压制**：场上只剩 **2 名存活玩家**（含恶魔）
2. **剧本特殊胜利条件**：
   - **Vortox（沃托克斯）**：白天没有任何人被处决，邪恶阵营立即获胜
   - **其他特殊条件**：根据具体剧本和角色而定

### 关键说明

- 恶魔死亡后，若场上仍有可继承的爪牙（如 Scarlet Woman），则游戏继续
- 若恶魔死亡且无法产生新恶魔，善良阵营立即获胜
- 部分角色的能力可能改变正常的胜负判定逻辑（如 Mastermind 的延迟死亡）

## 6. 特殊机制

### 6.1 死亡处理

| 规则 | 说明 |
|------|------|
| 死后发言 | 死亡玩家仍可在白天发言，参与讨论 |
| 遗言票 | 死亡玩家在次日的投票中仍有一次投票权 |
| 失去投票权 | 使用遗言票后，死亡玩家不再拥有投票权 |
| 能力保留 | 部分角色死亡后仍可能触发能力（如 Ravenkeeper、Sweetheart） |

### 6.2 说书人裁定

说书人在血染钟楼中扮演核心仲裁角色：

- **信息提供**：许多角色的信息由说书人直接提供
- **随机事件裁决**：决定 Poisoner 毒谁、Pit-Hag 变什么角色等
- **节奏控制**：宣布白天/夜晚的转换
- **规则解释**：处理边界情况和规则冲突

### 6.3 中毒与醉酒

| 状态 | 效果 | 来源 |
|------|------|------|
| **中毒**（Poisoned） | 角色能力失效或获得**错误信息** | Poisoner、No Dashii 邻座、Vigormortis 效果等 |
| **醉酒**（Drunk） | 角色能力失效或获得**错误信息** | Drunk、Sailor、Innkeeper、Minstrel 等 |

- 中毒/醉酒的角色可能**以为自己能力正常**，但实际上：
  - 信息类角色会获得说书人提供的**假信息**
  - 保护类角色无法真正保护目标
  - 击杀类角色无法真正击杀目标
- 说书人决定给真信息还是假信息时，会考虑当前阵营态势

### 6.4 私聊

- 支持玩家间**一对一私聊**
- 私聊内容仅对话双方可见
- 私聊可在白天阶段进行
- 可通过配置参数 `allowPrivateChat` 开启/关闭

## 7. 玩家说书人模式

### 7.1 模式说明

- 游戏开始前由**房主指定一名玩家**担任说书人
- 说书人**不参与游戏**（不会被分配角色）
- 说书人拥有专属的操作面板执行各项操作

### 7.2 说书人职责

| 职责 | 具体说明 |
|------|----------|
| **提供信息** | 为信息类角色提供调查信息（可选择给正确或错误信息） |
| **随机事件裁决** | 决定 Poisoner 毒谁、Pit-Hag 变什么角色等随机事件结果 |
| **节奏控制** | 宣布白天/夜晚的转换，控制游戏节奏 |
| **操作执行** | 通过操作面板执行各种说书人操作 |
| **规则仲裁** | 处理角色能力的边界情况和规则冲突 |

### 7.3 说书人操作面板

说书人可通过操作面板执行：
- 查看当前游戏状态（存活玩家、角色分配等）
- 为信息类角色提供信息
- 处理角色能力的结算
- 控制游戏阶段切换
- 执行特殊事件（如 Pit-Hag 角色变换）

## 8. AI 说书人模式

AI 说书人模式由系统自动主持游戏，AI 会根据预设策略做出各种裁决。

### 8.1 三种偏好设置

AI 说书人有三种偏好模式，影响其在裁决时的倾向：

| 模式 | 标识 | 说明 |
|------|------|------|
| **维持平衡** | `neutral` | AI 尽量选择有利于当前**弱势方**的选项，使游戏保持悬念 |
| **偏向好人** | `good` | AI 保护关键好人角色，给坏人错误信息，倾向于善良阵营 |
| **偏向坏人** | `evil` | AI 优先击杀关键好人，给好人错误信息，倾向于邪恶阵营 |

### 8.2 恶魔击杀目标选择策略

#### 8.2.1 维持平衡模式（`neutral`）

AI 首先判断当前阵营强弱：

```
阵营评估 = 存活好人数 + 剩余能力评估  vs  坏人数 + 剩余能力评估
```

- **如果好人强势**：优先击杀信息类镇民
  - 目标优先级：Fortune Teller > Empath > Investigator > Chef > 其他信息角色
- **如果坏人强势**：避免击杀关键镇民，选择击杀外来者或低风险目标
  - 优先击杀：Outsider > 已暴露的好人 > 无信息能力的镇民

#### 8.2.2 偏向好人模式（`good`）

- **避免击杀关键信息角色**（Merlin-like 角色）
- 给恶魔**假目标引导**
- 优先让恶魔击杀：
  - 价值较低的目标（已使用能力的角色）
  - 外来者（部分外来者死亡对好人有利）
  - 被保护的目标（让恶魔浪费攻击）

#### 8.2.3 偏向坏人模式（`evil`）

- **优先击杀关键信息角色**：
  - 首杀目标：Empath、Fortune Teller、Oracle 等核心信息源
  - 次杀目标：保护类角色（Monk、Soldier、Tea Lady）
- **保护恶魔不被发现**：
  - 给信息角色指向非恶魔目标
  - 让 Spy 被检测为善良角色干扰调查

### 8.3 关键平衡规则（硬编码限制）

以下规则为**硬编码限制**，AI 说书人必须遵守，不受偏好模式影响：

#### 8.3.1 Pit-Hag（深渊女巫）限制

> **规则**：如果场上已有存活恶魔，AI 说书人**绝不会**允许 Pit-Hag 变出第二个恶魔。

- 如果 Pit-Hag 试图将一名玩家变成恶魔，而场上已有存活的恶魔，AI 会选择**其他角色**代替
- 此限制确保游戏不会因多个恶魔而崩溃

#### 8.3.2 Scarlet Woman（猩红女郎）继承

> **规则**：当 Imp 死亡时，如果场上有 Scarlet Woman，她会继承成为新的 Imp。

- 在平衡模式下，AI 会确保这个机制**正常触发**
- 继承顺序由座位距离决定（最近的 Scarlet Woman 继承）
- 这是邪恶阵营维持战斗力的核心机制

#### 8.3.3 信息真实性控制

> **规则**：Poisoner 的目标如果是信息角色，AI 在平衡模式下会根据阵营态势决定给真信息还是假信息。

- **好人强势时**：可能给中毒的信息角色**真信息**（帮助好人）
- **坏人强势时**：给中毒的信息角色**假信息**（扰乱好人）
- 中毒/醉酒状态本身不改变，但说书人提供的信息质量会调整

## 9. 配置参数

### 9.1 完整配置参数表

| 参数名 | 类型 | 可选值 | 默认值 | 说明 |
|--------|------|--------|--------|------|
| `edition` | string | `trouble-brewing` / `bad-moon-rising` / `sects-violets` | `trouble-brewing` | 选择官方剧本 |
| `dayTime` | number | 0 ~ 3600（秒） | `null` | 白天时间（秒），`0` 或 `null` 表示不限时 |
| `nightTime` | number | 0 ~ 3600（秒） | `null` | 夜晚时间（秒），`0` 或 `null` 表示不限时 |
| `allowPrivateChat` | boolean | `true` / `false` | `true` | 是否允许玩家间一对一私聊 |
| `storytellerMode` | string | `player` / `ai` / `none` | `ai` | 说书人模式 |
| `aiBias` | string | `neutral` / `good` / `evil` | `neutral` | AI 说书人偏好（仅 AI 模式有效） |
| `storytellerId` | string | 玩家 ID | `null` | 玩家说书人的玩家 ID（仅玩家模式有效） |

### 9.2 配置示例

#### 新手友好配置

```json
{
  "edition": "trouble-brewing",
  "dayTime": 300,
  "nightTime": 120,
  "allowPrivateChat": true,
  "storytellerMode": "ai",
  "aiBias": "neutral"
}
```

#### 高阶玩家配置

```json
{
  "edition": "sects-violets",
  "dayTime": 0,
  "nightTime": 0,
  "allowPrivateChat": true,
  "storytellerMode": "player",
  "storytellerId": "player_123"
}
```

#### 纯好人保护模式

```json
{
  "edition": "bad-moon-rising",
  "dayTime": 600,
  "nightTime": 180,
  "allowPrivateChat": false,
  "storytellerMode": "ai",
  "aiBias": "good"
}
```

## 10. 后端逻辑说明

### 10.1 数据层

| 模块 | 文件 | 说明 |
|------|------|------|
| 角色数据 | `botcData.ts` | 包含完整的官方角色定义，包括角色名称、类别、能力描述、行动顺序等 |
| 技能实现 | `botcSkills.ts` | 按官方规则实现所有角色的技能逻辑，包括信息获取、保护、击杀等 |

### 10.2 游戏流程控制

- **夜间行动顺序**：严格按照官方**首夜顺序表**和**其他夜顺序表**执行角色唤醒
- 每个角色的技能按官方规则进行结算
- 被动效果（如 Scarlet Woman 继承、No Dashii 影响邻座等）**自动处理**，无需手动触发

### 10.3 AI 说书人模块

- **独立的目标选择算法**：根据偏好模式和当前阵营态势选择最优目标
- **信息质量调控**：动态调整提供信息的真实性
- **硬编码平衡规则**：确保核心游戏机制不被破坏（如 Pit-Hag 限制、Scarlet Woman 继承等）

### 10.4 被动效果自动处理

以下被动效果由系统自动处理：

| 效果 | 触发条件 | 自动操作 |
|------|----------|----------|
| Scarlet Woman 继承 | Demon 死亡且存活非旅行者玩家 >= 5 | 最近的 Scarlet Woman 自动变为 Demon |
| No Dashii 邻座中毒 | No Dashii 存活 | 自动使左右邻座的镇民持续中毒 |
| Vigormortis 爪牙保留 | Vigormortis 杀死爪牙 | 被杀的爪牙保留能力并自动使一名镇民中毒 |
| 死亡遗言票 | 玩家死亡 | 自动在次日投票阶段保留一次投票权 |
